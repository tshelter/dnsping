# v0.1.0 — cross-platform GUI (keep dnsping design idea)

## Goal
Take the Windows dnsping GUI as the design reference and re-implement the same idea on macOS
and Linux with each OS's native UI toolkit. The GUI layout/idea is the same everywhere; only
the toolkit changes per OS.

### Reference (already done — Windows)
- `dnsping/` is the reference implementation.
- Single window: target field, query-mode dropdown (DNS 0x20 / DNS random subdomain / ICMP / HTTP HEAD),
  domain field, rate/duration/timeout dropdowns, output-folder path + browse, live graph, stats line,
  progress, Start/Stop, Analyze, MTR, Pack & share.
- Modes: DNS cached-name (0x20), DNS random subdomain, ICMP ping, HTTP HEAD (curl -I equivalent).
- Session folder + CSV logging (ping.csv, mtr.csv, events.log, wifi.csv, iface.csv, system.txt, readme.txt)
  with zip pack & share on clipboard.

### GUI idea to carry across OSes
- One main window with the same sections and flow as dnsping.
- Same four probe modes where the OS supports them; same rate/duration/timeout controls.
- Same live graph + stats + start/stop semantics.
- Same "Pack & share" idea (zip the session folder, put it on the clipboard / share sheet).
- Same built-in analyzer idea (timeline + outage list) where practical.

### Per-OS toolkit decision
- Windows: keep dnsping as-is (native Win32).
- macOS: AppKit (native macOS UI). Need a Cocoa build path for the probe core.
- Linux: use the desktop environment's native UI convention. The Linux GUI should match macOS
  parity in features/idea, implemented with whatever is the natural Linux native toolkit for this
  kind of small utility. Decide concretely during implementation (e.g. GTK) — the point is a real
  native look, not a portable widget layer pretending to be the same on every OS.

### Shared core
- Factor the probe logic (DNS 0x20/random, ICMP, HTTP HEAD) and session-folder/CSV logging into a
  shared core usable by all three GUIs, so the three front ends stay thin and the behavior stays
  consistent.
- Platform probes must use the platform's real APIs (not Windows-only Winsock/WinHTTP/icmpapi on macOS/Linux).

### Scope for v0.1.0
- macOS GUI prototype with the same idea.
- Linux GUI prototype with the same idea.
- Shared core factored out.
- Session folder + CSV parity where the platform supports it.
- Verify build+run on each platform, then cut v0.1.0 signed release.
- Keep Windows dnsping as the existing reference; do not rewrite it.

## Notes
- dnsping design is good — preserve the idea, not the pixels. Each OS gets its own std design libs.
- Don't overbuild: v0.1.0 is "same GUI idea everywhere, native toolkit per OS", not a full feature clone
  of every monitor/MTR nicety if the platform makes that a big job. Capture the core idea first.
